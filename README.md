# Dee’s Cyber Corner

A responsive, dependency free static portfolio for GitHub Pages. The homepage uses the owner’s cyber studio design reference with live HTML branding, headings, links, and the Progress over Perfection message. The site uses locally hosted fonts and optimized WebP artwork.

## Develop

```sh
python3 -m http.server 8000
```

No package installation, compilation, or credentials are required to serve the site.

## Shared components

Header and footer markup live in `components/header.html` and `components/footer.html`. After editing those templates, run:

```sh
python3 scripts/build_shared.py
```

This writes the shared navigation as static HTML, adjusts relative paths, and marks the current section. It also attaches the shared world stylesheet and interaction script. Asset versions are derived from the shared stylesheet and script so changes refresh correctly in browsers. The command is idempotent. Rendering does not rely on JavaScript.

- `assets/css/site.css`: typography, existing layouts, and original component styles.
- `assets/css/world.css`: the shared charcoal/crimson visual system and room layouts.
- `assets/js/site.js`: mobile navigation and project filters.
- `assets/js/world.js`: Explore transition, resource search/filtering, career explorer, and contact handling.

## Pages

- `index.html`: single screen cyber studio homepage at typical screen sizes, with readable reflow in short windows.
- `about.html`: the owner’s personal story, portrait, education, growth, and life beyond technology.
- `labs.html`: project workspace with actual Sentinel evidence and filterable case studies.
- `resources.html`: Dee’s Holy Grail (favorites, ADHD study methods with a focus timer, certification prep, college tips) and the filterable Resource Library. Generated by `scripts/build_resources.py`; edit the lists there, then run it and `scripts/build_shared.py`.
- `careers.html`: Paths in Tech, with 15 areas grouped into team rows (blue, red & purple, white, yellow, and support) and role/project guidance. `scripts/build_careers.py` builds the rows. No quiz.
- `contact.html`: public GitHub link and an accessible email draft form.
- `blog.html`: the owner’s published first story.
- `projects/`: detailed Sentinel, Entra, Okta, cloud, and GRC case studies. EDR is explicitly in preparation.

## Contact delivery

The public email link was found in the owner’s GitHub profile README. By default, the form validates the visitor’s fields and opens their email app with a prepared message. It does not claim the message was sent; the visitor must review and send it there. Without JavaScript, a direct email link is available and the form button is disabled to avoid an unintended form submission.

For direct website delivery, create and verify a form endpoint with a service such as Formspree, then put the HTTPS endpoint URL in `data-endpoint` on `#contact-form`. The shared script switches the button and explanatory copy, POSTs FormData, and reports acceptance or failure. No API secret should be placed in the page. Test with the chosen service before announcing direct delivery. A form service has **not** been connected yet.

## Interaction and accessibility checks

The Explore sequence lasts about 1.65 seconds: dimming, a red scan, the existing butterfly asset, ACCESS GRANTED, NEW LEVEL UNLOCKED, and a completing progress indicator. Navigation uses the native link first; the sequence plays on arrival and cannot block the destination. Continue now or Escape dismisses it and focuses the destination heading. A timer also dismisses it if animation frames stop. Storage or animation errors leave normal navigation usable. Focus stays within the temporary dialog. Back/forward navigation clears transient state. Reduced motion skips the sequence. Modified clicks retain native link behavior. Homepage entrance cues and logo/light movement run once. Story reveals are progressive enhancements; content remains visible without JavaScript and for reduced motion. The shared search/filter handler remains available for future resource content, but the Resources page is intentionally blank and has no cards or search controls. Mobile menus expose expanded state and support Escape.

Browser checks use Playwright and axe-core from the development environment, not shipped website dependencies. With the server at port 8000 and Playwright available:

```sh
node tests/world-interactions.cjs
node tests/cinematic-navigation.cjs
```

Validation covers desktop, tablet, and phone layouts, accessible navigation, internal files and anchors, WCAG A/AA automated checks, blank Resources, project filters, career panels, contact validation and email draft creation, no JavaScript fallbacks, the Explore animation, and reduced motion. Automated checks do not replace human accessibility testing.

## Rooms, game layer, and living portrait

- `assets/css/rooms.css`, `assets/js/rooms.js`: interior pages share the homepage look: studio-art hero band, circuit network canvas, scan sweep, decrypting eyebrow, card tilt, pointer spotlight, scroll progress, and a Keep exploring row of homepage tiles.
- `assets/css/game.css`, `assets/js/game.js`: each room is a level (About 01, Projects 02, Paths in Tech 03, Resources 04, Blog 05, Contact 06). Visiting unlocks a level, real actions earn achievements, and the header HUD opens a mission map. Progress is stored only in the visitor's browser and can be reset there.
- `assets/css/hq-eyes.css`, `assets/js/hq-eyes.js`: on the homepage, both irises shift inside their eye openings (following the mouse or glancing on their own) and a periodic facial-scan overlay locks on. The artwork file is unchanged; moving layers are masked copies of it.

`scripts/build_shared.py` attaches the rooms files to interior pages and the game files to every page. All motion is disabled for reduced motion.

### Adding a blog story

Each story lives in `stories/`. To publish a new one, copy `stories/how-i-broke-into-cybersecurity.html`, change the title, meta description, eyebrow, and body, then add a matching `.story-card` to the `.story-grid` in `blog.html` (newest first) and replace or remove the "being written" card. Run `python3 scripts/build_shared.py` afterwards.

### Lab walkthroughs

Every case study links to a step-by-step walkthrough (`projects/*-walkthrough.html`). The honeypot walkthrough is hand-written; the others are generated by `scripts/build_walkthroughs.py` from the content in its `LABS` list, which follows Dee’s GitHub write-ups. Edit the list, then run `python3 scripts/build_walkthroughs.py && python3 scripts/build_shared.py`.
