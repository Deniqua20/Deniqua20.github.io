Identity and access · Case study

One identity.
Thoughtful access.

An Okta lab focused on SAML single sign on, SCIM provisioning, group based access, and identity lifecycle workflows.

The problem

Access can become inconsistent when application assignments and user changes are managed separately. This lab explores centralized authentication and a repeatable way to manage access as people join, change roles, or leave.

Tools and technologies

Okta, SAML 2.0, SCIM 2.0, Okta System Log, and the Okta API are listed in the published lab writeup.

Methodology

The published writeup documents Okta as the identity provider, SAML assertion mappings for a connected application, SCIM provisioning, and application assignments driven by job function groups.

Joiner, mover, and leaver scenarios cover creating an account, changing group membership, and deactivating the user. The writeup also describes reviewing Okta System Log events and exporting logs for SIEM use.

Documented findings and validation

The documented checks include testing the SSO flow and claims, confirming provisioning for assigned users, and reviewing deprovisioning when a user is deactivated. The related SSO lab documents Google Workspace integration and access denial for unassigned users.

Lessons and takeaways

Federation separates the identity provider from the application. Group based assignments make access easier to reason about, while lifecycle changes and logs provide concrete places to check whether the intended access change occurred.
