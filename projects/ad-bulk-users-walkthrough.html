Identity and access / Lab walkthrough · Beginner

Bulk-create 50 AD users
and sync to Entra ID.

Build a lab domain, generate 50 fictional users, create them all at once with PowerShell, and watch them show up in Microsoft Entra ID.

Windows ServerActive DirectoryPowerShellCSVMicrosoft Entra ConnectMicrosoft Entra ID

Why I built this lab

Creating users one at a time doesn’t scale. I wanted to practice bulk provisioning with PowerShell, then see how on-premises Active Directory accounts sync to the cloud with Microsoft Entra Connect, the hybrid identity setup a lot of companies still run.

Make it your own. This is how I did it, not the only way. Feel free to adjust the lab to your liking: change the names, tools, or scope, or take it further. What matters is that you understand what you built and why.

Before you start

  • Windows Server (the free evaluation ISO).
  • VirtualBox or Hyper-V to run the server as a virtual machine.
  • Excel or Google Sheets to check the CSV.
  • An AI tool like ChatGPT or Claude to generate fictional users (or use my sample CSV below).
  • A Microsoft Entra ID tenant you can test in. Signing up for a free Azure account creates one, and you’re its Global Administrator. Sign-up asks for a card to verify you, but this lab stays in the free tier.
  • A computer with at least 8 GB of RAM (16 GB is smoother) and about 80 GB of free space, with virtualization turned on. If VirtualBox says virtualization is off, turn on Intel VT-x or AMD-V in your BIOS settings.
  • Time: about 2 to 3 hours. Cost: free. The Windows Server evaluation lasts 180 days.
  • Fictional data only. Never use real employee information.

What you’ll learn

  • Installing Active Directory and creating an organizational unit (OU)
  • Building a CSV that maps to Active Directory attributes
  • Bulk-creating users with a PowerShell script
  • Hybrid identity with Microsoft Entra Connect
  • Verifying users on-premises and in the cloud

Lab files · fictional data

Grab the files

⬇ Sample CSV, 50 fictional users (.csv) ⬇ PowerShell script (Import-LabUsers.ps1)

Every name in the sample CSV is made up. The AI prompt is in step 4.

How it fits together

  1. AI promptGenerates 50 fictional users.
  2. CSV fileOne row per user, one column per attribute.
  3. PowerShellCreates every user in the LabUsers OU.
  4. Entra ConnectSyncs the OU to the cloud.
  5. Microsoft Entra IDThe users appear, synced from on-premises AD.

Step by step

  1. Build your Windows Server virtual machine

    1. Download the Windows Server evaluation ISO from the Microsoft Evaluation Center. It’s a large file, so give it time.
    2. Install VirtualBox, open it, and click New.
    3. Name the VM (for example DC01), choose your downloaded ISO, and give it at least 2 CPUs, 4 GB of RAM, and a 60 GB disk. If VirtualBox offers an “unattended install,” you can uncheck it and install by hand.
    4. Start the VM. When Windows Setup asks which edition, pick one that says (Desktop Experience), so you get the normal Windows interface.
    5. Choose Custom: Install Windows only, select the empty disk, and let it install.
    6. Set a password for the Administrator account and sign in. In VirtualBox, use Input → Keyboard → Insert Ctrl-Alt-Del to reach the sign-in screen.
    7. Rename the server: open Server Manager → Local Server, click the computer name, change it to DC01, and restart.

    Tip Leave the VM’s network on the default (NAT) so the server has internet access. You need it later for Microsoft Entra Connect.

  2. Install Active Directory and create your domain

    1. Open Server Manager.
    2. Click Manage → Add Roles and Features.
    3. Select Active Directory Domain Services, then click Install.
    4. When it finishes, click Promote this server to a domain controller.
    5. Choose Add a new forest and enter your lab domain. I used ad.lab.example.com.
    6. Set a DSRM password, click through the wizard, and click Install. The server restarts on its own.
    7. Sign back in as AD\Administrator (your domain name, a backslash, then Administrator) with the same password as before.

    Tip The wizard may show yellow warnings, such as a DNS delegation warning or a dynamic IP address. In a lab those are fine. Click Install anyway.

    Prefer PowerShell? This does the same thing:

    powershell
    Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "ad.lab.example.com"

  3. Create an organizational unit (OU)

    1. Open Active Directory Users and Computers.
    2. Right-click your domain, then New → Organizational Unit.
    3. Name it LabUsers and click OK.
    powershell
    New-ADOrganizationalUnit -Name "LabUsers" -Path "DC=ad,DC=lab,DC=example,DC=com"

    Tip Keeping lab users in their own OU makes them easy to find, sync, and clean up later.

  4. Generate 50 fictional users with AI

    Paste this prompt into ChatGPT or Claude. Change the domain if yours is different.

    prompt
    Create 50 fictional employee records for an Active Directory lab. Use these CSV headers: FirstName,LastName,SamAccountName,UserPrincipalName,DisplayName,EmailAddress,Department,Title. Use unique usernames, the domain ad.lab.example.com, and example.com email addresses. Include IT, HR, Finance, Operations, Marketing, and Cybersecurity. Return only valid CSV data.

    Tip Don’t want to use AI? Download my sample CSV above. It’s 50 made-up users, ready to go.

  5. Save the CSV file

    1. Create a folder: C:\IAMLab.
    2. Paste the data into Excel. If everything lands in one column, use Data → Text to Columns with a comma delimiter.
    3. Click File → Save As, choose CSV UTF-8 (Comma delimited), and save it in C:\IAMLab as AD_BulkUpload_50Users.csv.

    Tip No Excel? Paste the CSV text into Notepad, choose File → Save As, set Save as type to All files, and name it AD_BulkUpload_50Users.csv.

    Check it: you should have 1 header row and 50 user rows.

  6. Test the CSV in PowerShell

    Click Start, type PowerShell, right-click Windows PowerShell, and choose Run as administrator. Then make sure the file loads:

    powershell
    Import-Module ActiveDirectory
$Users = Import-Csv "C:\IAMLab\AD_BulkUpload_50Users.csv"
$Users.Count

    Expected result: 50.

  7. Run the bulk import script

    Save this script as C:\IAMLab\Import-LabUsers.ps1 (or download it above), then run it. It asks for one temporary password, creates every user in the LabUsers OU, and skips anyone who already exists.

    powershell
    <#
  Import-LabUsers.ps1  (Dee's Cyber Corner)
  Bulk-creates lab users in Active Directory from a CSV file.
  For lab use only. Use fictional data, never real employee records.

  Usage (in an elevated PowerShell window on your domain controller):
    cd C:\IAMLab
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    .\Import-LabUsers.ps1

  Change -CsvPath or -OU if your file name or domain is different.
#>
param(
  [string]$CsvPath = "C:\IAMLab\AD_BulkUpload_50Users.csv",
  [string]$OU = "OU=LabUsers,DC=ad,DC=lab,DC=example,DC=com"
)

Import-Module ActiveDirectory

# One temporary password for every new user. Users must change it at first sign-in.
# It has to meet your domain's password rules (length and complexity).
$password = Read-Host -AsSecureString "Enter a temporary password for the new users"

$users   = Import-Csv -Path $CsvPath
$created = 0
$skipped = 0

foreach ($u in $users) {
  # Skip anyone who already exists, so the script is safe to run more than once
  if (Get-ADUser -Filter "SamAccountName -eq '$($u.SamAccountName)'" -ErrorAction SilentlyContinue) {
    Write-Host "Skipped (already exists): $($u.SamAccountName)" -ForegroundColor Yellow
    $skipped++
    continue
  }
  try {
    New-ADUser -Name $u.DisplayName `
      -GivenName $u.FirstName -Surname $u.LastName `
      -SamAccountName $u.SamAccountName -UserPrincipalName $u.UserPrincipalName `
      -DisplayName $u.DisplayName -EmailAddress $u.EmailAddress `
      -Department $u.Department -Title $u.Title `
      -Path $OU -AccountPassword $password `
      -ChangePasswordAtLogon $true -Enabled $true
    Write-Host "Created: $($u.SamAccountName)" -ForegroundColor Green
    $created++
  } catch {
    Write-Host "Failed: $($u.SamAccountName) - $($_.Exception.Message)" -ForegroundColor Red
    $skipped++
  }
}

Write-Host ""
Write-Host "Import complete"
Write-Host "Created: $created"
Write-Host "Skipped: $skipped"
    powershell
    cd C:\IAMLab
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\Import-LabUsers.ps1

    Expected result: Created: 50, Skipped: 0.

    Tip Saving the script yourself? In Notepad, set Save as type to All files. Otherwise Windows saves it as Import-LabUsers.ps1.txt and PowerShell can’t find it. Turn on File name extensions in File Explorer’s View menu to check.

    Tip The temporary password has to meet your domain’s password rules (length and complexity), or every user will fail. Users must change it at first sign-in.

  8. Verify the users in Active Directory

    Open Active Directory Users and Computers, expand your domain, and click LabUsers. Or count them with PowerShell:

    powershell
    (Get-ADUser -SearchBase "OU=LabUsers,DC=ad,DC=lab,DC=example,DC=com" -Filter *).Count

    Expected result: 50.

  9. Install Microsoft Entra Connect Sync

    1. Sign in to the Microsoft Entra admin center and go to Identity → Hybrid management → Microsoft Entra Connect, then download Connect Sync.
    2. Run the installer on your server. In this lab that’s the domain controller.
    3. Choose Customize, then Password Hash Synchronization.
    4. Sign in with your Entra admin account (the one from your Azure sign-up). Approve the MFA prompt if it asks.
    5. Connect your Active Directory domain. When asked for enterprise admin credentials, use AD\Administrator.
    6. On the sign-in warning, choose Continue without matching all UPN suffixes to verified domains.
    7. Under Domain and OU filtering, select only LabUsers.
    8. Finish the setup and let it start the first sync.

    Tip In a real company, Entra Connect runs on its own server, not the domain controller. For a lab, one server is fine.

  10. Run a sync with PowerShell

    The first sync starts automatically. To push changes right away, run:

    powershell
    Import-Module ADSync
Start-ADSyncSyncCycle -PolicyType Delta

    Expected result: the sync request is accepted with no errors. Use -PolicyType Initial for a full sync after changing settings.

  11. Verify the users in Microsoft Entra ID

    1. Go to entra.microsoft.com → Users → All users.
    2. Search for one of your users (for example, Andrea McKee).
    3. Open the user and check that On-premises sync enabled says Yes.

    Tip Because example.com isn’t a domain you own, the synced users sign in as name@yourtenant.onmicrosoft.com. That’s normal for a lab.

Check your work

  • Your CSV has 1 header row and 50 users.
  • The script reports Created: 50.
  • All 50 users are in the LabUsers OU.
  • Entra Connect is installed and syncing only LabUsers.
  • The sync ran with no errors.
  • Your users show in Entra ID with on-premises sync enabled.

Clean up

Uninstall Microsoft Entra Connect, then delete the synced test users in Entra ID. Synced users stay in the cloud until you remove them. Delete the VM when you’re done.

Interview ready

Be ready to explain

  • Why bulk provisioning with a script beats creating users by hand.
  • How each CSV column maps to an Active Directory attribute.
  • Why the script skips existing users, so it’s safe to run more than once.
  • What Entra Connect does, and why password hash sync is a common choice.
  • Why you filtered the sync to one OU, and what the UPN suffix warning means.
